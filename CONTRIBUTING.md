# Contributing an Artifact

This project models surface EMG artifacts as a pipeline of modular processors. This guide shows you how to add your artifact to that pipeline without breaking anything when the simulator runs.

## Before you start

1. **You can run the simulator on `main`.** Follow the README setup. If `python emg_simulator.py` opens a window with eight scrolling channels and the gesture buttons respond, you are ready.

2. **You have read `src/artifacts/base.py`.** Three abstract methods, about twenty lines of code. That file is the contract you are implementing.

## The mental model

The simulator holds a list called `self.artifacts`. On every batch of samples, it walks the list and applies each artifact's `process()` method in order. On every sample-rate change, it walks the list and calls each artifact's `rebuild(new_fs)`. Your job is to write a class that fits into that list.

Start your branch from `main`:

```bash
git checkout main
git pull origin main
git checkout -b artifact/<your-name>
```

Use a short slug for `<your-name>`: `motion`, `electrode-shift`, `fatigue`, `powerline`. Lowercase, hyphens not underscores.

## How the simulator calls your code

Three touchpoints. Understanding these is the whole guide; everything below is filling them in.

**Touchpoint 1: the constructor.** When the simulator starts up, it instantiates your class once, passing `n_channels` and `fs`. Whatever fs-dependent state you need (filter coefficients, time-constant conversions) you set up here. Whatever user-facing state you have (intensity, target level) you initialize to a safe default.

**Touchpoint 2: `process(emg, sample_rate)`.** Called on every batch of samples generated by the simulator, hundreds of times per second. Input shape is `(n_samples, n_channels)` and output must be the same shape. If your artifact is "off," return the input unchanged with as little work as possible.

**Touchpoint 3: `rebuild(sample_rate)`.** Called when the user changes fs at runtime via the dropdown. You recompute fs-dependent things (filter coefficients, anything proportional to Nyquist). You leave user-facing state alone (the intensity slider value, accumulated phase, anything the user expects to survive a rate change).

There is a fourth method, `reset()`, called at the start of a new recording. It clears runtime state (filter delay lines, phase counters) without touching user-facing state.

## Things to get right so nothing breaks at runtime

**Shape contract.** `process()` accepts `(n_samples, n_channels)` and returns the same shape. If your processing is per-channel, vectorize with NumPy broadcasting rather than looping. The simulator runs at kHz rates and a Python channel loop will drop frames.

**Pass-through at zero.** Your `process()` runs on every batch whether the user has enabled your artifact or not. If your zero-state code path does real work, you pay that cost for nothing. An early `return emg` when intensity is zero is the standard pattern. `SweatProcessor` returns the original array (not a copy) at zero; that is correct.

**State separation in `rebuild()`.** Filter coefficients depend on the new sample rate, so recompute them. The intensity slider value does not depend on the sample rate, so preserve it. If a teammate drags fs from 1000 to 2000 and the slider snaps back to zero, you reset something you should not have.

**The `sample_rate` argument to `process()`.** Required by the contract. Whether you read it inside `process()` or rely on `self.fs` (which `rebuild()` keeps current) is your choice. `SweatProcessor` accepts but ignores it; the simulator guarantees they match.

## Validate the class in isolation

Before wiring the artifact into the simulator, confirm it satisfies the contract on its own. Save this as `scratch_test_<your-name>.py` at the repo root:

```python
import numpy as np
from src.artifacts.<your-name> import YourArtifact
from src.artifacts.base import BaseArtifact

art = YourArtifact(n_channels=8, fs=1000)
assert isinstance(art, BaseArtifact)

emg = np.random.randn(100, 8)
out = art.process(emg, 1000.0)
assert out.shape == emg.shape

assert np.array_equal(out, emg), 'should be pass-through at intensity 0'

art.set_intensity(0.5)
out = art.process(emg, 1000.0)
assert not np.array_equal(out, emg), 'should modify signal at intensity 0.5'

art.rebuild(2000.0)
assert art.fs == 2000.0
assert art._intensity == 0.5

out2 = art.process(emg, 2000.0)
assert out2.shape == emg.shape

print('All contract checks passed.')
```

Run it:

```bash
source .venv/bin/activate
PYTHONPATH=. python scratch_test_<your-name>.py
```

If any assertion fails, fix the class before going further. Debugging a `BaseArtifact` subclass on its own is much easier than debugging it through a Tkinter event loop in a background data thread.

## Wire it into the simulator

Three edits.

**Edit 1: import the class in `emg_simulator.py`.** Find this near the top:

```python
from src.artifacts import BaseArtifact
```

Add your import below it:

```python
from src.artifacts.<your-name> import YourArtifact
```

**Edit 2: construct and append in `EMGSimulatorApp.__init__`.** Find the artifact list initialization:

```python
self.artifacts: list[BaseArtifact] = []
```

Add your artifact below it:

```python
self.your_artifact = YourArtifact(
    n_channels=N_CHANNELS,
    fs=DEFAULT_FS,
    seed=42,
)
self.artifacts.append(self.your_artifact)
```

The named reference (`self.your_artifact`) is for the UI to talk to directly. It points to the same object as `self.artifacts[-1]`.

**Edit 3: export from the package.** Open `src/artifacts/__init__.py` and add your class:

```python
from src.artifacts.base import BaseArtifact
from src.artifacts.<your-name> import YourArtifact

__all__ = ["BaseArtifact", "YourArtifact"]
```

Now run the simulator:

```bash
PYTHONPATH=. python emg_simulator.py
```

It should open and behave exactly as before. Your artifact is in the pipeline at intensity 0.0, so the pass-through guard makes it invisible. If the simulator crashes, your import or constructor is wrong; the traceback will say where.

## Add UI to control your artifact

This is the most artifact-specific part, because every artifact has different controls. A sweat slider works for continuous intensity. A motion artifact might want a tap-to-trigger button. A fatigue artifact might want a stopwatch readout. Decide what fits your physics.

For a continuous-intensity artifact, copy the sweat slider pattern. Look at the `# -- Sweat control --` block in `_build_ui` on the `artifact/sweat` branch; it gives you a labeled slider, a live readout, and a reset button. Adapt the names and the callback.

For other patterns, use your judgement. The simulator's UI lives in two places:

- `_build_ui` builds the widgets at startup. Your widget goes here, packed into the `ctrl` frame between the existing LabelFrames.
- `_apply_theme` restyles widgets when the user toggles light or dark mode. Your widget needs a corresponding block here.

Your UI callbacks should talk to `self.your_artifact` directly, not poke into `self.artifacts` by index. That is the whole point of the named reference:

```python
def _on_intensity_change(self, value_str):
    value = float(value_str)
    self.your_artifact.set_intensity(value)
    self.intensity_label.config(text=f"Intensity: {int(value * 100)}%")
```

## Final integration check

With your UI in place, exercise the full path:

1. Open the simulator.
2. Hold a non-rest gesture.
3. Move your control from off to on. Confirm the signal changes in the way your physics predicts.
4. Change the sample rate dropdown. Confirm your control's value is preserved across the rate change.
5. Toggle the theme. Confirm your UI restyles without leftover colors.

If any of these break, the symptom maps to a specific touchpoint: a missing pass-through guard, a `rebuild()` that resets user state, or a missing entry in `_apply_theme`.

## Where to look when stuck

- `src/artifacts/base.py`: the contract.
- `src/artifacts/sweat.py` (on `artifact/sweat`): a complete worked example.
- `emg_simulator.py` on `main` versus `artifact/sweat`: the diff shows you exactly what an artifact branch adds.
